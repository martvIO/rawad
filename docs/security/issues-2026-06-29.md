## Issue 1 — F-1 (frontend): upgrade `aws-amplify` to clear Amplify-pinned npm advisories

**Labels:** `security`, `dependencies`, `frontend`

**Severity:** High (1 critical advisory) — but **low real-world exploitability**

**Body:**

`npm audit` in `frontend/` reports 18 transitive vulnerabilities (17 moderate + 1 **critical** `fast-xml-parser`), all in the `aws-amplify` → `@aws-sdk/*` chain. They could **not** be fixed in the 2026-06-29 audit:

- `npm audit fix --force` bumps `vite` v5 → v8, which breaks `npm install` (`@vitejs/plugin-react@4` peer-requires vite ≤ ^7) and the JSX test runtime — reverted.
- An `overrides` pin of `fast-xml-parser@^5.9.3` triggers an ERESOLVE conflict with Amplify's bundled `@aws-sdk/core`.
- The critical `fast-xml-parser` only parses **trusted AWS API responses over TLS** (not attacker input), so exploitability in the browser is low.

**Task:** in a dedicated branch, upgrade `aws-amplify` / `@aws-amplify/ui-react*` to the latest 6.x (or 7.x), re-run `npm audit`, and **fully regression-test the Face-Liveness + Rekognition "your photos" flow** (Playwright MCP) before merging. Do not `--force`.

**Acceptance:** `npm audit --omit=dev` in `frontend/` reports 0 high/critical; `npm install` resolves cleanly; build + 500 unit tests + Liveness e2e pass.

## Issue 2 — F-2: rotate `LEMONSQUEEZY_API_KEY` (shared in plaintext chat)

**Labels:** `security`, `secrets`

**Severity:** Medium

**Body:**

`backend/functions/.env.local` carries the comment *"Rotate `LEMONSQUEEZY_API_KEY` after testing — it was shared in plaintext chat."* The key is gitignored and was **never committed** (confirmed by a full-history gitleaks scan), but a key that transited a plaintext channel must be treated as exposed.

**Task:**
1. Rotate the API key in the **Lemon Squeezy dashboard** (revokes the old one).
2. Update the value in `backend/functions/.env*` (local) and the production secret (`firebase functions:config` / Secret Manager).
3. Confirm `/pay/:token` checkout + the `order_created` webhook still work.

**Acceptance:** old key revoked; payments + webhook verified against the new key.

## Issue 3 — F-3: remove unused `STRIPE_SECRET_KEY` from local `.env`

**Labels:** `security`, `secrets`, `cleanup`

**Severity:** Low

**Body:**

`backend/functions/.env` sets `STRIPE_SECRET_KEY` (and possibly `STRIPE_WEBHOOK_SECRET`), but **no code reads `process.env.STRIPE_*`** — Stripe appears only in dormant comments/config; **Lemon Squeezy is the active payment provider**. The file is gitignored/local. Unused secrets are needless exposure surface.

**Task:** remove the unused `STRIPE_*` entries from the local `.env` (or document why they're retained for a planned Stripe integration).

**Acceptance:** no unused payment secrets in local env files, or a one-line note explaining retention.

## Issue 4 — F-4: de-hardcode admin-SDK-key paths in `.claude/settings.local.json`

**Labels:** `security`, `config`

**Severity:** Low

**Body:**

`.claude/settings.local.json` (tracked in git) embeds **absolute filesystem paths** to the Firebase admin-SDK key inside PowerShell/Bash command strings, e.g. `C:\Users\martv\...\dawa-aa793-firebase-adminsdk-fbsvc-...json`. This leaks a username + local directory layout (not the key itself — the key file stays gitignored) and is machine-specific (already wrong for other contributors).

**Task:** parameterize via `$GOOGLE_APPLICATION_CREDENTIALS` or a repo-relative path so no absolute machine path is committed; verify the admin scripts (`fixAdminClaim.js`, `inspectUser.js`, etc.) still authenticate.

**Acceptance:** no absolute per-developer path in the tracked settings file; admin scripts still run.
